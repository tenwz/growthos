The problem

问题

An agent can write a hundred claims in a minute.
It cannot tell you which ones are true.

Agent 一分钟能写 100 条营销结论。
它无法告诉你哪一条是真的。

Teams end up with an untraceable doc of “insights,” a content calendar that repeats what the founder already believed, experiments that end in a vibe, and an AI that confidently invents a quote.

于是团队得到一份无法追溯的「洞察」文档、一个不断重复创始人原有想法的内容日历、以「感觉还行」收尾的实验，以及一个会自信编造客户原话的 AI。

signal→claim→receipt→decision

The bottleneck is not generation. It is memory and evidence. growthOS makes both enforceable.

真正的瓶颈不是生成，是记忆与证据。growthOS 让这两件事可以被强制执行。

Six systems

六个系统

Three are real software. Three are complete job specs.

三个是真实软件，三个是完整 job spec。

v0.1 is deliberately narrow. It ships the evidence loop, not a suite of dashboards.

v0.1 刻意收窄：先交付证据闭环，而不是一堆仪表盘。

software

Customer Truth

Capture verbatim signals. Compile a weekly memo. Reject every claim without a receipt.

software

Creative Testing

Hypothesis → result with a receipt → scale / iterate / kill → written learning.

software

Growth Cockpit

One static HTML file. Evidence coverage, failing claims, experiment ledger, score.

job spec

Founder Content

One real signal → one specific post. No listicles, no invented vulnerability.

job spec

Outbound Signal

Public signal → angle → draft. A human approves and sends. No auto-DM.

job spec

AI Search Visibility

Find the questions where assistants cite others, then build the source they quote.

The scoreboard

记分牌

100 points. Deterministic. Auditable.

100 分，确定性，可审计。

No LLM judge in the total. Every point maps to a behavior you can inspect. Synthetic demos are labeled and can never be certified.

总分不含 LLM 打分。每一分都对应一个可检查的行为。合成 demo 会被标记，永远不能认证。

Quickstart

快速开始

See it fail correctly in three seconds.

三秒内看它正确地失败。

The demo is the whole thesis: a confident memo fails the build because one claim has no receipt. Then a defensible memo passes and the cockpit scores the system.

Demo 就是整个论点：一份自信的 memo 因为一条结论没有收据而无法通过构建；然后一份站得住脚的 memo 通过，cockpit 给整个系统打分。

Start with the quickstart Full guide
# 1. the demo npx growthos demo # 2. your repo npx growthos init my-growth-os --agent all cd my-growth-os # 3. a real signal npx growthos capture \ --source x_post \ --url "https://x.com/acme/status/123" \ --quote "We tried an AI SDR for a month..." # 4. audit the claim npx growthos doctor --strict # 5. score + cockpit npx growthos score --explain npx growthos cockpit --no-open

Open by construction

天然开放

Your data stays in your repo. Your model stays your choice.

数据留在你的仓库，模型由你选择。

Plain files

Markdown + YAML. Diff every claim in a pull request. No database, no export, no lock-in.

Model-agnostic

A default command provider for claude, codex, or Ollama; an OpenAI-compatible adapter. Manual paste always works.

Agent-native

Six Agent Skills, a local stdio MCP server, and a prompt compiler that treats customer text as untrusted data.

Complements the skills you already use. Keep marketingskills for copy craft. growthOS is the memory, the receipts, and the decision log underneath.

和你已有的 Skills 一起用。 marketingskills 负责文案和定位；growthOS 是它下面的记忆、收据和决策日志。
